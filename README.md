# NR-inspired OFDM Validation Harness

This repository implements a small, deterministic OFDM transmit/receive path for validating wireless-signal processing behavior. It uses a 64-subcarrier resource grid with QPSK data, known pilot subcarriers, a cyclic prefix, a flat complex channel, and configurable complex Gaussian noise.

The project is intentionally scoped as an engineering validation harness rather than a complete 3GPP implementation. It does not claim 5G NR protocol compliance, LDPC coding, MIMO, scheduling, or RF hardware integration. The purpose is to make signal-processing assumptions executable, measurable, and testable.

## What it demonstrates

- QPSK modulation and hard-decision demodulation.
- OFDM IFFT/FFT processing with cyclic-prefix insertion and removal.
- Pilot-based flat-channel estimation and equalization.
- Deterministic noise injection for reproducible failure analysis.
- EVM and BER measurements with requirements-based pass/fail decisions.
- A machine-readable CLI report suitable for CI artifacts or a larger test system.

## Requirements traceability

The validation checks are documented in [`docs/requirements.md`](docs/requirements.md). The Python tests cover modulation, cyclic-prefix behavior, pilot estimation, nominal operation, and noisy-case rejection.

## Setup

```powershell
python -m venv .venv
.\.venv\Scripts\activate
python -m pip install -e ".[dev]"
```

On macOS or Linux, activate with `source .venv/bin/activate`.

## Run the validation suite

```powershell
python -m pytest
```

Run a nominal frame and print JSON metrics:

```powershell
python -m nr_validation.cli --scenario nominal
```

Run a deliberately noisy frame to exercise the rejection path:

```powershell
python -m nr_validation.cli --scenario noisy
```

## Example output

The exact metrics are deterministic for the documented seed and are generated by the CLI at runtime.

## Architecture

```text
nr_validation/
  cli.py          command-line entry point and JSON reporting
  models.py       immutable configuration and result models
  modulation.py   QPSK mapping and hard-decision demapping
  ofdm.py         grid construction, OFDM framing, channel, and metrics
  validation.py   requirements-based scenario evaluation
tests/            pytest unit and integration checks
docs/requirements.md  requirement-to-test traceability
.github/workflows/ci.yml  repeatable Python CI
```

## Limitations and trade-offs

- The channel is flat and complex-valued; it is not a multipath or RF model.
- The implementation uses a small grid and QPSK only; it does not implement the full NR physical layer.
- Noise is deterministic when a seed is supplied so failures can be reproduced.
- NumPy is used for clarity and reference behavior; this is not an optimized real-time implementation.
